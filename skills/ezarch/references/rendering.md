# Blender 渲染操作

用户要求 AI 使用 Rhino 渲染出图时，先执行 [Rhino 渲染出图的暂行限制与两次风险确认](rhino-mcp.md#rhino-渲染出图的暂行限制)，不能直接沿用本页的 Blender 渲染流程或擅自切换应用。

三维主线见 [建模与操作](blender-modeling.md)。直接用 bpy 可创建或修改几何、材质、灯光、相机和渲染配置。[原生操作](edit-existing.md#blender) 说明如何延续用户场景。相机、细节和画面风格由任务决定。

## 基于完成设计的生成式渲染

Blender 可直接完成渲染。生成式图像的唯一用途是对已经完成的设计成果代替渲染：设计已落实到本次阶段所需深度，具有可核对的模型或图纸，所需画面的形体、空间及其他设计选择已有依据。可使用用户提供的已完成成果，无需重建；概念项目不必深化成施工模型，但几块未定体量或仅一份文字方案不能由生图补成完整设计。立面材料分区、固定家具和景观配置等影响本次成果的选择，也不能借“表现深化”交给生图补定。

采用此方式时，基于真实设计取得对应镜头的底图或足以确定画面的图纸，再进行图像表现。按工具实际支持选用视图、线稿、遮罩或深度等辅助输入，不假定工具拥有几何锁定能力。单独平面图无法确定的高度、遮挡和外形，应先通过设计补足，而非交给生图猜测。材质、光照与氛围表达服务于已有设计；不以生图承担构思、素材制作或改变建筑设计。

多个视角分别使用同一设计的对应视图作为依据，前一张生成图可辅助保持表现一致，但不能成为另一视角唯一的几何依据。实际对照模型/图纸和生成图的轮廓、比例、楼层、开口、构件、交通及已定材料和配置，不能以“保持结构”的提示词保证一致。发生设计漂移则修正或使用 Blender 渲染，不把漂移当作已批准的设计修改。

保留可编辑源成果、对应底图及最终图，说明采用了生成式渲染及其核对范围。精确尺寸、技术标注与模型几何仍以源文件为准。此方式依赖宿主可用工具，EZarch 不捆绑或要求 imagegen；不可用时继续采用 Blender，不静默换成付费接口。设计方案中说明拟采用的制作与表现方式，已有授权无需重复确认。

## 随库入口

`render <input> --camera <name|all> --out <dir>` 接收 BLEND/GLB/GLTF/OBJ/PLY/STL 或 EZarch scene.json。OBJ/PLY/STL 需 `--source-units mm|m`。输入为 BLEND 时默认保留引擎、采样、色彩管理、曝光、透明背景、分辨率、图像格式、灯光及原相机名称；输出写到指定目录。

`--width` 和 `--samples` 只覆盖相应设置。`--quality preview|final` 是显式的分辨率/采样预设；已有 BLEND 不传它就沿用场景。新导入的裸模型使用 Cycles/AgX 与预览默认值，可在脚本中改写。中文及含特殊字符的相机使用可移植文件名映射，不重命名场景对象。

默认保存渲染图和 scene.blend 副本；`--no-save-blend` 仅渲染，不保存场景副本。已有场景沿用图像文件格式（例如 PNG/JPEG/EXR）；视频配置需要先在 bpy 中设为本次需要的静态图像格式。无论是否保存副本，都有轻量执行记录。

## 可复用操作

- `scripts/blender_scene.py` 提供材质、资产导入、灯光、相机与设备选择函数，适合按当前需求取用。
- scene.json 入口把 mm 转为 m；已有 BLEND 保留其坐标与单位。网格和素材的原点、尺度、朝向决定是否对齐。
- PBR 的贴图重复尺度、法线和色彩空间影响材质表现。随库 `texture_size_m` 为米制；自定义着色器可直接使用节点 API。
- Cycles 采样、降噪、反弹次数和分辨率影响成像；真实细节仍来自几何、材质、光照和构图。打印像素可由最终放置尺寸与目标 PPI 计算。
- 新场景可探测 CPU/GPU；已有 BLEND 保留设备设置，失败时根据日志处理，避免静默改变用户场景配置。

新生成场景保存时打包支持的图像依赖；已有 BLEND 默认保留依赖组织，需要独立交付时可主动调用 `bpy.ops.file.pack_all()`。程序材质、参数历史和第三方依赖的跨格式保留程度见 [格式说明](exchange-verification.md)。

公开素材及导入方式见 [资源入口](public-assets.md)。内置素材类别和预设不是 Blender 能力范围。

## 质量深化

先处理会改变画面的空间、构造和材质关系：门窗深度、楼地面交接、家具尺度/朝向/活动空间、边缘倒角、材质接缝、UV及贴图物理尺度。程序材质和真实贴图都可按目标使用；不需要所有项目写实，但写实目标不能靠提高采样替代几何深化。

导入素材检查完整依赖和实际包围尺寸，材质颜色纹理与数据纹理使用适当色彩空间；资产摆放服务于使用逻辑。光照对应场景光源和开口，曝光保留亮部/暗部信息，检查悬浮物、重复纹理、玻璃和接触阴影。镜头按设计叙事组织，避免用夸张广角扭曲尺度。实际查看与任务有关的整体和局部，发现问题回到几何/材质/灯光修改。公开素材入口可扩展，不要求使用单一资源供应商。


## 进一步表现与合成

Cycles/Eevee、白模、风格化材质、线条表达、透明背景、剖透视和爆炸表达可按任务选择，不由 preview/final 两个预设限定。需要艺术方向时依据用户参考决定材质、色调、镜头与空间叙事。节点 API 可直接控制 Principled、自定义节点组、Geometry Nodes 材质属性、世界着色器和 compositor。

按交付需要输出 EXR/图像、深度、法线、Cryptomatte、AOV 或 Light Groups，组合遮罩和灯光调整；具体接口按 Blender 版本查 [渲染通道](https://docs.blender.org/manual/en/4.5/render/layers/passes.html)。技术标注和图板文字可交由 SVG/PDF 模块，避免将低分辨率渲染文字当成可编辑技术图。

先用适合当前判断的预览观察空间、造型、材质尺度与光照，再对有意义的区域或最终尺寸增加精度。预览设置只为节省计算，不能作为最终质量上限；也不需要所有镜头均用最高采样。高面数素材用实例、合理细节层级和视图范围管理；用实际 GPU/CPU 探测与日志判断设备可用性。

社区资源和节点组见 [社区接入](blender-ecosystem.md)。画面检查同时关注使用逻辑、尺度、支承、穿插、悬浮、重复纹理、噪点、曝光和主体阅读；根据本次需求决定问题重要性与修改范围，不套固定镜头/图量清单。
