# 地图与分析参考

地图资料、太阳位置与影长计算，以及 SVG / 地理数据的表达方法。

## 数据与坐标

用户提供的规划图、调查或现有数据可直接作为输入。需要补充公开道路/建筑时，可查 OpenStreetMap：[署名](https://www.openstreetmap.org/copyright)、[Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)。查询范围和使用方式受对应服务规则约束。OSM 只是示例来源；政府规划、统计、论文、其他地图和用户资料都可按问题选择，必要时主动联网扩展资料与方法。

图像坐标适合栅格描绘和关系表达；真实距离/面积计算需要相应尺度或投影。经纬度不是米，图像对齐残差也不是地面测量精度。SVG 的 viewBox 与打印纸面尺寸可分别设置，无需改成建筑模型的毫米坐标。

统计图可直接使用 JSON/CSV/表格：比例的分母、范围、年份以及分类是否互斥决定计算方法。描绘的地图轮廓与资料表格是不同的数据来源；历史联系、规划和现状也可能采用不同表达。不存在必须绘制的图表类型或数量。

## 已有计算助手

`ezarch.analysis.solar_position(latitude, longitude, when)` 使用带时区时间计算太阳方位/高度；`shadow_vector(height_mm, sun)` 计算水平地面影长。NOAA 近似算法不含复杂地形、反射、大气折射或法定日照时数求解。

需要真实遮阴可投影体量几何；需要采光、能耗或风环境定量结果可选专门求解器。简单箭头和上述太阳助手本身不产生这些模拟结果。选择概念策略表达时，所称结果与实际方法相符即可，不要求补做性能模拟。

地图符号、标注、图例和统计图可直接程序生成 SVG；[矢量与排版工具](diagrams-boards.md) 提供相关入口。无需建立房间表或三维模型。
